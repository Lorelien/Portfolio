Terwinneke — Accessible Mobile UX

For the User-Centered Design course, I designed a mobile, accessible website for Frituur Terwinneke in Denderwindeke.

In this UX case study, I redesigned the existing website according to the WCAG 2.1 level AA guidelines, with a focus on screen readers, colour contrast and a low-threshold order flow in Figma.

The assignment

We were assigned to design a mobile-first accessible website or app for a hospitality business. The website had to include a homepage, an information page, a menu or drinks list, an order option without payment with a happy and unhappy flow, and a contact page.

We started with wireframes and then developed the final design in Figma. Throughout the process, we took WCAG level AA into account, including readable typography, real content, a large-text view, accessibility annotations, ten documented success criteria and a colour contrast matrix for the brand colours.

Analysis of the existing website

Before I started designing, I analysed Terwinneke’s existing website. The information page was empty and users had to create an account first in order to order. This created an unnecessary barrier for visitors who wanted to order something quickly.

The sauce selection was also confusing: the options were in a horizontally scrollable row and the promised images were missing. These pain points formed the basis for a clearer, more logical and more accessible website.

Target group

Terwinneke targets local residents and passers-by who want to quickly check the menu, opening hours, location or order options. The website must make this information immediately and easily accessible.

I also explicitly took people with visual impairments into account, including screen reader users and visitors who need large text, strong contrast and a clear structure. This makes the website more user-friendly for everyone.

My approach

I started with an analysis of the existing website and translated the main problems into a content structure and user flows. After that, I developed mobile-first low-fidelity wireframes, before refining them into high-fidelity designs in Figma.

Accessibility remained central throughout the entire process. I documented my choices with accessibility annotations, a colour contrast matrix and ten applied WCAG success criteria. The result is a mobile-first design aimed at WCAG level AA.

From wireframes to design

I started with mobile-first wireframes to determine which information is essential on a small screen. By using real text instead of Lorem Ipsum, I could assess the content and hierarchy realistically.

The wireframes included all required pages and flows: home, info, menu, order, contact and a happy and unhappy flow. After that, I translated the structure into a clear design with sufficient white space, readable typography and a limited colour palette.

I checked font size, line height and colour contrast according to WCAG level AA. In addition, I visualised a screen with extra large text to show the experience for visitors with limited sight.

Accessibility in practice

Accessibility was the common thread throughout the project. I designed a logical reading order from top to bottom and from left to right, so that screen readers can read the content in a comprehensible order.

With accessibility annotations, I indicated buttons, links, images, decorative images, headings and input fields, among other things. This makes it clear to developers how each element should be implemented accessibly.

I also created a colour contrast matrix for the brand colours and documented ten applied WCAG success criteria. In doing so, I took contrast, clear labels, focus order and alternative text for informative images into account, among other things.

Result

The final result is a mobile-first website for Terwinneke that combines usability and accessibility. The site includes all required pages and functionalities, with a clear structure, logical navigation and attention to readability.

Key improvements compared to the original website are:

  • An informative “Info” page instead of an empty page.
  • An order process without mandatory account registration.
  • A clear sauce selection with clear visual support.
  • A logical reading order for screen readers.
  • Sufficient colour contrast and clear typography.
  • Accessibility annotations that support developers in implementation.

No user tests were conducted, as the assignment focused on applying accessibility principles. The design does form a strong basis for a website aimed at WCAG level AA.
